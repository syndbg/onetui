# onetui-tui

Navigation state, request identity/cancellation, terminal lifecycle and rendering. Tests cover shell state, dynamic columns, chunked cached field detail and real PTYs. This package also owns keyboard/request-state and actual-CLI PTY journeys against PostgreSQL fixtures; connector contracts remain in their connector package. Local filter/sort reorder visible indices only, preserving native paging tokens and cached row identity.

## Layout

Context is the top panel, with `read-only` in its title; there is no separate branding/alias strip. At 60 columns and 20 rows or larger, it shows the connection alias, datasource, resource path, loaded/shown item counts and transport state. These counts describe cached data, not a database-wide total. At 100 columns, the panel also shows primary keys for actions available in the current context, using the existing action descriptors. Browsing, text entry and theme selection share aligned hints: bold colored keys (`Enter`, `Esc`, `Backspace`) on the left, descriptions on the right. Smaller terminals use a one-line read-only/alias/breadcrumb header. See [UI panels](../../docs/ui.md) for the panel map and responsive layout rules.

Press `?` for help with aligned Key, Command and Description columns, colored keys and alternating row backgrounds. Descriptions wrap within their column. Below 62 terminal columns, entries stack key/command above their wrapped description. Help lists the currently available action descriptors; command IDs can be entered with `:`. No keybindings or configuration settings change with this presentation.

The command/filter bar appears below context only while typing. It shows `:` or `/` and the entered text inside a plain border, without titles or key hints. Context owns mode-specific controls. After input closes, the table takes the bar's space; applied filters appear in its title and sort direction uses column arrows. Long input scrolls horizontally to keep the edited end visible. Below 12 terminal rows, the bar becomes one unbordered line. Press `/` and type `4b` to filter immediately; Enter keeps the result and Esc restores the previous filter and selection. Filtering reuses cached projections without reformatting values. Press `:`, type `themes`, then Enter to open the theme menu.

Enter on a data row opens all fields as a Field / Type / Value list. Select a field and press Enter again for its full cached value. Complete single-value browsing results, including Qdrant payloads, open directly in the value viewer. Native query results stay in a table even when they contain one cell. Esc returns one level; navigation adds no datasource read. These behaviors need no configuration keys.

`e` / `:query` opens a compact editor above retained rows. Enter or F5 executes; Shift+Enter inserts a newline. Ctrl-R also executes. Results stay visible during editing, loading and errors. Successful execution focuses the table and leaves the executed query visible above it. `e` edits again; Esc closes the editor first, then returns from results to browsing. Screen scrolling uses the remaining table height. OneTUI requests disambiguated keyboard events and restores the previous mode before leaving the alternate screen, including on panic. See [native query controls and terminal requirements](../../docs/queries.md).

The row inspector divides the available width between Field (25%), Type (25%) and Value (50%, including rounding). Its focused field expands from the retained value without preview truncation; other fields and the main record table remain compact. PageUp/PageDown scrolls a long expanded value by a screen; Ctrl-U/Ctrl-D scrolls half a screen. Short values retain screen-wise field navigation. `j/k` or `h/l` selects another field and resets value scrolling. Enter opens dedicated detail. Formatting is cached for the selected field; viewport wrapping scans bounded retained data and byte views generate one chunk at a time. `n/p` still changes datasource pages or value chunks. Command/filter input and theme/display menus ignore the screen-scrolling shortcuts.

Context hints keep `n/p` visible even when paging is unavailable. Loading keeps the same shortcut positions; inactive keys are muted. The action guards still prevent reads while loading or beyond the available pages. This presentation behavior has no configuration setting.

Page history keeps incoming provider tokens separately from cached rows. `p` restores one of the two cached previous pages or explicitly refetches an evicted page. Each view retains at most 4,096 previous-page bookmarks and 1 MiB of bookmark token text; forward paging stops at the limit without erasing the route back. Failed/cancelled backward reads keep their bookmark. Successful refresh clears history, and leaving the connection discards it. Bookmarks require no configuration or provider-specific TUI code; refetches are independent reads, not snapshots.

Providers can declare a follow resource, enabling `f` / `:follow`. The same worker fetches a finite batch, then schedules the next one after one second. The live window retains at most 100 rows and 1 MiB of page data plus separately bounded projections/previews. Old rows are evicted with a visible count; quiet polls reuse previews. `f`, Ctrl-C, navigation, inspection and command entry stop following before changing the view. Stale batches are rejected by generation. Stopped data stays readable; starting again captures a new end, while refresh returns to historical browsing. No new configuration keys or provider-specific renderer branches are needed.

The table has rounded borders, alternating dark rows, a contrasting selected row and arrows for page-local sort direction. NULL cells are muted but retain their literal label. The two-line footer holds status and paging, with the version reserved at bottom-right; terminals below 12 rows show status only, and widths below 40 columns hide the version. Loading, errors and ready states use palette-specific status colors with text labels; a connected transport does not mean live data refresh. The context panel never reads or displays connection strings, URLs or secret values. This layout uses the existing theme and input settings; it adds no configuration keys.

Run `make run` from the workspace root with fixtures already running. `?` opens action descriptions. `T` or `:themes` opens all ten palettes: `j`/`k` or arrows preview, Enter keeps for this session, Esc or Ctrl-C restores the previous theme. The menu preserves navigation and pending reads and does not write configuration. Top-level `theme` sets the startup palette, defaulting to Catppuccin; restart to read a configuration change. See [names, variants and configuration](../theme/README.md). The `onetui-theme` crate owns RGB roles; this renderer converts them to Ratatui colors. Every screen uses the same palette, with no per-theme renderer or provider branch.

## Validation

`v` / `:display` selects field formats and session display switches. The value module validates JSON with Serde's borrowed `RawValue`, preserves JSON lexemes, escapes untrusted text and renders bounded byte chunks. Existing Unicode segmentation/width dependencies cover grapheme boundaries and layout. Derived previews and detail text are cached separately from retained values and stable filter/sort projections. See [display controls and limits](../../docs/ui.md#value-display-controls).

The worker owns a generic executor for one selected alias, with one active request and one replaceable pending request. Descriptors supply entry resources and navigation targets. Production code imports no connector or database SDK; PostgreSQL is a dev dependency for this package's live journey. Session/request identities reject stale pages, errors and transport status. Unix input uses Crossterm's polling backend; the PTY journey also checks repeated resize/input interleaving.

Live tests run both full browsing journeys in one CLI process: PostgreSQL rows/detail, an active-query switch to Qdrant paging/payload/vectors/metadata, then a successful return to PostgreSQL. The Qdrant client is a dev-only fixture seeder; it creates and removes the test's own collection, including cleanup after an assertion panic. Connector protocol/value assertions remain in their packages, without a parameterized backend harness.

Separate tests inject worker panic, uncooperative reads and stalled shutdown through a test-only provider wrapper. Exact terminal flags and PostgreSQL PIDs are checked before the fault-test child exits, so process termination cannot hide a leaked driver. PostgreSQL's native client is a dev-only observer dependency; no production backend branch or fault-injection option is added.

```sh
make build
cargo test -p onetui-tui --locked
```

Run from the workspace root. `make verify` checks all packages. Keep connector tests and helpers package-local, even when setup is duplicated; do not parameterize a test harness over PostgreSQL and Qdrant. Cross-alias worker coordination belongs here.

See [configuration](../../README.md#configuration) for settings, defaults, accepted values and examples, and [PostgreSQL usage](../../docs/postgres.md) for navigation and fixed limits. Enter on a relation opens rows; use `m` for column metadata, `/` for a case-sensitive page filter and `s` for selected-field lexical sort. Run `make test-integration` for the live TUI journey and separate connector suites.
